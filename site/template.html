Cozy ASCII scenes that react to your agent while it works

Your agent's session, drawn as a landscape. Each element carries one thing you would otherwise read for: activity, the last tool call, the helpers, failures, context left, and the moment it needs you. Same window, any terminal agent. An event protocol with a scene on top.

One session, sped up. The agent runs untouched in the top rows; everything under it is drawn from what it is doing. The first turn is the owl's, on the mountain vista; at the second prompt the scape is the shore and the crab takes it. Either is one command, and a running scape switches on its next frame.

{{bg:wait}}
  • ActivitySee how hard it is working, and what it just did. The sea says how much: more and taller swells as it works, flat water while it waits on you; on the vista, the wind and the fire. The sand says what: every tool call and the file it touched, the newest brightest.
  • NotificationsLeave the room. One sound when it needs an answer, another when it is done, a third when it finished with something broken. Silent otherwise.
  • SubagentsCount the helpers. A crablet on the sand, or an owlet by the owl, for each subagent running. It leaves when its job is done.
  • FailuresNever miss a failed command. It shows on the companion's face until your next prompt.
  • Context meterSee the context running out before it compacts. The moon sinks as the window fills, and from 40% used the number left is written under it.
  • ProgressWatch the work add up. A star for every finished turn or todo, each falling into its place in the sky.
  • Your clockKeep your own hours. The sky is the real time of day where you sit, so no two sessions look the same.

The owl on its own, in its five states. Press one. The crab has the same five, its own way.

{{bg:get}}

Three commands, no app, no tab, no tmux, nothing to build. The install writes the agent's hooks after a backup; then the agent runs on top and the scape underneath, in the same window, so you never look away from the work to see the work.

$ curl -fsSL https://donlucasx.github.io/xscapes/install.sh | sh # Mac or Linux, with or without Go

Claude Code

$ xscapes install claude --apply $ xscapes claude

Kimi Code CLI

$ xscapes install kimi --apply $ xscapes kimi

Hermes Agent

$ xscapes install hermes --apply $ xscapes hermes

Anything else

$ xscapes inside <any command> # no hooks needed

Coming soon: Codex CLI, Gemini CLI, OpenCode.

{{bg:layer}}

xscapes is a set of ASCII landscapes and companions that react as your agents work. Every scape carries the same six things: a light, a sky, something that moves with the work, a surface, somewhere the work piles up, and someone who lives there. So any of them tells the same story.

The mountain vista ships as the default. Swap landscapes or companions with one command, mid-session included; a running scape picks it up on its next frame.

Hero the crab. The shore's companion.

The cat. Came first. One command away.

The owl. The vista's companion: five faces, owlets for subagents.

The frog. Drawn for the aquarium. Next.

The mountain vista, with the owl. The default. The wind is the work: still air is a straight column of smoke and upright grass; as the agent gets busy the smoke streams sideways, the scrub flattens and the air fills. The fire lights the meadow at night, and the peaks take the last light at dusk.

The shore, with the crab. The sea is the work: more and taller swells as the agent works, flat water while it waits, and the tide comes up the beach with it. Crablets for subagents, the moon over the water, the last tool calls written in the sand.

The rainy window, with the cat. Rain on the glass is the work: harder as the agent gets busy, then easing. The city behind it carries the hour. Drawn; next.

The aquarium, with the frog. More fish come out as the work picks up, the tank's lamp is the light, and the gravel is where it settles. Drawn; next.

$ xscapes scape shore # or vista, the default $ xscapes companion cat # or crab
{{bg:month}}

Underneath the scene is an event protocol. An adapter turns what an agent does into a few events on a socket; the engine draws the session from those alone and knows nothing about any agent.

session_start session_end prompt tool_start tool_end error test_pass test_fail compact needs_input answered done sub_start sub_end todo context interrupt

Claude Code, Kimi Code CLI and Hermes Agent ship with adapters made of their own hooks; anything else is watched through its output. A new adapter is whatever emits the events:

$ xscapes emit tool_end -tool Read -target internal/auth/handler.go $ xscapes emit needs_input -text "allow Bash?"

And it is not a loop: the sea is the work, the sand the last few actions, the sky your own clock, so no two sessions draw the same picture. It asks nothing of you, and the agent's output reaches your terminal byte for byte, never in the way of the work.

Every scene on this page is the real renderer folding the events a Claude Code session emits — text, not video, drawn by the same code that runs in your terminal. Nothing is posed.
