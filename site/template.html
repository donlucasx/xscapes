You send a prompt and the terminal goes quiet. A spinner, a verb that changes every few seconds, and nothing else: not whether this is a five-second read or a five-minute refactor, not that a command just failed, not how much context is left before it compacts. So you tab away, and come back late.

Cozy ASCII scenes that react to your agent while it works

Every character below is a fact about the agent — not a filter over a picture. The page is drawing what your terminal draws.

One session, sped up. The agent runs untouched in the top rows. Everything under it is drawn from what it is doing.

  • Leave the room. A solid balloon and one sound when it needs an answer, a dotted balloon and a different sound when it is done. Silent while it works, so the two you hear are the two that matter.
  • Know what it is doing without reading the screen. The sea says how hard it is working, the sand says what it just did, a crablet stands for each subagent it has running, and a failed command shows on the companion's face until your next prompt.
  • See the context running out before it compacts. The moon thins and sinks as the context fills, and from 40% used what is left is written under it as a number.

The same beach in five moments. Press one and only the thing that carries it changes — that is the whole language, and it is why you never have to read the screen.

Three commands. No app, no tab, no account, no tmux. It runs in the same window as the agent, which is the point: you never look away from the work to see the work.

$ go install github.com/donlucasx/xscapes@latest $ xscapes install claude --apply # writes its hooks, after a backup $ xscapes claude # the agent on top, the scape underneath $ xscapes inside <any command> # anything else, hosted the same way

The shoreline is the first scape, not the product. Underneath it is a small event protocol — session, prompt, tool, error, needs input, done, compact — and a thin adapter for each agent: Claude Code arrives wired through its own hooks, and anything else that runs in a terminal is hosted the same way. Any landscape that provides six things carries all of it unchanged: a light, a sky, something that moves with the work, a surface, somewhere the work piles up, and someone living in it.

Hero the crab ships as the default. The cat came first and is one command away; a running scape picks the change up on its next frame.

$ xscapes companion cat

The rainy window, with the cat. Rain on the glass is the work: watch it come down harder as the agent gets busy, then ease. The city behind it carries the hour.

The aquarium, with the frog. More fish come out as the work picks up, the tank's lamp is the light, and the gravel is where it settles.

One rule holds it together: activity, subagents, finished work and context left each own their own part of the picture, and nothing shares a channel. That is why a glance is enough.

It is not a loop. The sea is your agent's work and the sand is its last few actions, so no two sessions draw the same picture, and the sky runs on your clock. It asks nothing of you: no keys, no score, nothing to feed. And the agent's own output reaches your terminal byte for byte, so it can never get in the way of the work it is drawing.
